# 《风风博客·制片厂》产品需求文档（PRD）v1.0

> 项目：blog0fwindchan-studio（`studio` 分支）
> 作者：🎨 产品策划 ｜ 日期：2026-11-06 ｜ 状态：**产品定义完成，交接架构设计**

## 0. 一句话定义

把风风博客改造成一台「剧本驱动、逐帧可复现」的教学视频制片机：用户写一份 JSON 剧本，博客页面按帧时钟自动滚动、打字，目录桌宠说台词，顶栏放歌词，离线逐帧渲染成分段 MP4，用户再到 PR 里配音剪辑。

## 1. 用户与场景

- **主要用户**：用户本人（创作者 + 导演 + 配音）。
- **次要用户**：开源社区用户，只要求能用 example 配置跑通。
- **核心场景**：为一篇教程制作配套视频，片长 3~15 分钟，按「开场 → 安装 → 使用 → 效果 → 收尾」分成 5~15 个分段。背景板文章存在 studio 本地的 `blog.db` 里，是专门为拍片准备的副本，可以随意修改，不对外发布。

| 痛点                   | 解法                                   |
| ---------------------- | -------------------------------------- |
| 录屏鼠标乱飘、滚动不稳 | 画面里没有鼠标，页面滚动由剧本按帧插值 |
| PR 里手搓黑底白字字幕  | 字幕内化为 TocPet 台词气泡             |
| 缺统一视觉包装         | 博客原生 Aero 主题 + 顶栏歌词播放器    |
| 改一句节奏要重录       | 改 JSON 时长，只重渲对应分段           |

## 2. 产品原则（所有功能都要满足）

1. **确定性**：同一份剧本 + 同一时间点 t，必须渲染出同一帧。同一分段连续渲染两次，画面逐帧一致。
2. **可跳转（Seekable）**：任意时刻 t 的页面状态只由「剧本 + t」决定，不依赖"从头播放到这里"。时间轴拖拽和分段渲染都以此为前提。
3. **剧本是唯一权威**：演播室模式下，鼠标、滚轮、随机闲聊、真实时钟都不能改变画面。
4. **零侵入日常浏览**：Studio 能力全部挂在演播室模式开关后面，普通浏览行为不变。
5. **隐私靠配置**：私人路径、歌单缓存、录屏原片、数据库全部走 `.gitignore`，仓库只放 example。
6. **仓库单向流动**（最高优先级的工程约束，见 §2.1）。

### 2.1 仓库关系：upstream → studio 单向

```
upstream: futurelesswindchan/blog0fwindchan (main)  ──合并──▶  origin: windchan-studio/blog0fwindchan-studio (studio)
                           ▲                                              │
                           └──── 博客本身的问题：回到 upstream 仓库修 ◀───┘（只是"发现"，不是"推送"）
```

| 规则                            | 说明                                                                                                                                       |
| ------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| R1 upstream → studio 可以       | studio 定期合并 upstream 的改动，保持博客本体最新                                                                                          |
| R2 studio → upstream 永远不行   | studio 的任何代码、配置、依赖、数据都不得进入 upstream，不发 PR、不 cherry-pick                                                            |
| R3 博客本身的问题回 upstream 修 | studio 开发中发现的博客 bug 或遗留问题（如 backdrop-filter 性能），在 upstream 仓库里独立修复，再由 R1 合并回 studio。不在 studio 里就地修 |
| R4 判断标准                     | 改动"公网博客也需要吗？"需要 → 属于 upstream；只为拍片服务 → 属于 studio                                                                   |
| R5 降低合并冲突                 | studio 改动优先放在新增文件和演播室模式开关后面，尽量少改 upstream 已有文件的内部逻辑                                                      |

推论：

- studio 可以放心修改博客已有代码来服务拍片（如 `useArticleInfo.ts` 的锚点生成），不用考虑公网兼容。
- studio 本地 `blog.db` 里没有"已发布文章"，标题、锚点、内容都可以为了剧本随意改。

## 3. 功能分档与阶段路线

### 3.1 Phase 1 · MVP「能出第一支片」

**必须有（P0）**

- F1 演播室模式：URL 参数 `?studio=<剧本id>` 进入；关闭鼠标交互、随机闲聊、真实时钟。画面清场规则见 §7.0（隐藏侧栏、上一篇/下一篇按钮；只显示剧本投放的 toast）。退出演播室模式后全部恢复。
- F2 帧时钟（Frame Clock）：全局唯一时间源 `t(ms)`，支持 play / pause / seek / 逐帧步进。
- F3 剧本加载与校验：读取 JSON 剧本，按 JSON Schema 校验，错误定位到「第几段第几句」。
- F4 TocPet 字幕：台词文本、时长、情绪（含新增教学情绪）、目录展开/收起、高亮当前步骤。
- F5 页面编排：滚动到标题锚点 / 元素、打字机进度、代码块复制反馈、亮暗主题切换，全部由 t 驱动。
- F6 顶栏歌词条：读取预烘焙 JSON，按 t 只显示一行原文歌词，换行淡入淡出。支持歌单连播、歌间渐变、片尾 outro 结束语（§6.3）。
- F7 音乐烘焙（并入 studio 后端）：输入网易云歌曲 ID / 歌名，或一键识别 SMTC 当前播放，抓取歌词写成本地 JSON。入口为导演控制栏的「🎵 烘焙」面板（§7.4），不再依赖外部 ncm-lyrics-streamer 进程。
- F8 导演预览控制栏：浏览器内实时预览，时间轴拖拽，分段标记跳转，接收被拦截的系统 toast。
- F9 分段离线渲染：按分段 id 渲染 MP4，支持 24/30 fps、编码器可选（libx264 / h264_qsv / h264_nvenc）。
- F9.1 渲染清单 `manifest.json`：每段写明起止帧、时长、剧本 hash，以及本段用到的每首歌「在视频第几毫秒开始、从歌曲第几毫秒开始」。歌单连播后 PR 对音轨必须依赖它，因此从 P1 升为 P0。
- F14 剧本投放 toast：剧本可在指定时刻投放定时 toast（如 BGM 署名），每首歌开始时默认自动投放「♪ 歌名 - 歌手」。

**最好有（P1，Phase 1 末尾视时间加入）**

- F10 剧本热重载：保存 JSON 后预览页自动刷新到当前 t。
- F11 命令行烘焙：与 F7 面板共用后端逻辑的 CLI 入口，方便批量或脚本化。
- F12 增量重渲：剧本 hash 未变的分段自动跳过。
- F13 时长自动推算：未写 `duration` 时按语速公式给初值（见 §5.4）。

### 3.2 Phase 2 · 打磨

- 安全区预览线（字幕不被 PR 叠层挡住）、导出单帧 PNG 做封面。
- 多进程并行渲染不同分段。
- 歌词显示译文的开关（`lyric: original / translation`），按需再加。

### 3.2.1 TODO · 渲染性能（暂不设指标）

- 基线：真实文章页单进程 3.4 fps（约 296ms/帧），瓶颈在截帧，主要来自博客本身的 backdrop-filter 毛玻璃。
- 这属于博客本体的遗留问题，按 §2.1 R3 应在 upstream 仓库优化，再合并回 studio。
- Phase 1 只要求"能渲染、结果正确"，不设耗时验收线。基础功能稳定后再定性能目标。

### 3.3 Phase 3 · 图文混排与实操演示舞台（TODO）

- 画中画：在博客背景板上叠加实操录屏片段（C# / Android / WebView），由剧本控制入场、位置、缩放。
- 步骤浮层：大号步骤卡片、键位提示、高亮框。
- 本阶段在 Phase 1 剧本格式里**只预留 `overlay` 动作类型名**，不实现。

### 3.4 明确不做

- 实时录屏、音频轨（配音与 BGM 都在 PR 完成，渲染出的 MP4 无声）。
- 公网部署、多用户、剧本在线编辑器。
- 移动端布局（演播室固定 1920×1080 桌面布局）。
- 分段之间的转场效果（在 PR 里做更灵活）。
- 歌词封面、歌曲进度条、歌曲时间显示（§7.2）。
- 把任何 studio 改动回推 upstream（§2.1 R2）。

## 5. 数据契约一：视频分镜与字幕剧本（Script JSON）

### 5.1 设计取舍

- **顺序时间，不写绝对时间码**：台词按数组顺序首尾相接，每句只写自己的 `duration`。改一句时长，后面自动顺延，不用手算时间码。这是手写和 AI 生成都最不容易出错的形式。
- **动作挂在台词上**：滚动、展开目录等动作写在触发它的那句台词里，用 `at`（相对本句开始的毫秒）微调时机。台词和画面动作天然对齐。
- **分段 = 渲染单位 = 配音单位**：每个 `segment` 渲染成一个 MP4，也是 TOC 里的一个"步骤"。
- **状态可推导**：情绪、目录展开、主题等都是"持续状态"，任意 t 的状态 = 从片头扫描到 t 的最后一次设定值。这保证了可跳转（原则 2）。

### 5.2 结构总览

```
Script
├─ version, id, title
├─ article        → 用哪篇文章做背景板（slug）
├─ video          → 分辨率、fps、主题、默认值
├─ music?         → 歌单 tracks[] + 歌间渐变 + 自动署名 + 片尾 outro
└─ segments[]     → 分段（= 一个 MP4 = 一个教学步骤）
    ├─ id, title, tocAnchor?
    └─ lines[]    → 台词（= 一个字幕气泡）
        ├─ text, duration?, mood?
        └─ actions[]? → 画面动作（scroll / toc / typewriter / highlight / copy / theme / toast / wait / overlay）
```

### 5.4 字段说明

**顶层**

| 字段                   | 必填 | 说明                                                                                                                   |
| ---------------------- | ---- | ---------------------------------------------------------------------------------------------------------------------- |
| `version`              | 是   | 剧本格式版本，当前为 `1`                                                                                               |
| `id`                   | 是   | 剧本唯一 id，用于 URL `?studio=<id>` 和输出目录名，限 `[a-z0-9-]`                                                      |
| `article.slug`         | 是   | 背景板文章 slug，必须在本地 `blog.db` 中存在                                                                           |
| `video.fps`            | 否   | `24` 或 `30`，默认 `30`（性能目标暂缓，见 §3.2.1）                                                                     |
| `video.zoom`           | 否   | 页面缩放，等效浏览器缩放比例，默认 `1.1`（用户日常浏览用 110%，内容区刚好占满画面）。输出分辨率始终是 `width × height` |
| `video.theme`          | 否   | 片头初始主题 `light` / `dark`，默认 `dark`（深色对比度好、代码高亮醒目）。剧本中可随时用 `theme` 动作在亮暗间切换      |
| `video.defaults.mood`  | 否   | 台词未写 `mood` 时沿用上一句；首句未写时用此值                                                                         |
| `video.defaults.gapMs` | 否   | 两句台词之间气泡空白的间隔，默认 `300`                                                                                 |
| `music.tracks[]`       | 否   | 歌单，按顺序连播。每项 `ref`（烘焙 id，必填）、`startAtMs`（从歌曲第几毫秒开始放，默认 `0`）                           |
| `music.crossfadeMs`    | 否   | 歌与歌之间歌词条的渐变时长，默认 `1500`                                                                                |
| `music.announce`       | 否   | 每首歌开始时自动投放「♪ 歌名 - 歌手」toast，默认 `true`                                                                |
| `music.outro.text`     | 否   | 片尾结束语。不写时用代码内置的默认结束语                                                                               |

**segment**

| 字段        | 必填 | 说明                                                                         |
| ----------- | ---- | ---------------------------------------------------------------------------- |
| `id`        | 是   | 分段 id，渲染命令用它定位，输出文件名 `<序号>-<id>.mp4`                      |
| `title`     | 是   | 显示在导演控制栏和 TOC 进度里                                                |
| `tocAnchor` | 否   | 对应的文章标题（定位器写法见 §5.5.1）。进入本段时自动 `toc.highlight` 该标题 |

**line**

| 字段       | 必填 | 说明                                                                 |
| ---------- | ---- | -------------------------------------------------------------------- |
| `text`     | 是   | 台词，支持 `**加粗**` 和 `` `行内代码` `` 两种轻量标记，其余按纯文本 |
| `duration` | 否   | 本句停留毫秒数。缺省时用推算公式                                     |
| `mood`     | 否   | 情绪，见 §5.6；缺省沿用上一句                                        |
| `actions`  | 否   | 动作数组，见 §5.5                                                    |
| `note`     | 否   | 导演备注（配音提示等），只在控制栏显示，不进画面                     |

**时长推算公式（F13）**：`duration = clamp(600 + 中文字数 × 220 + 英文单词数 × 300, 1500, 8000)` 毫秒。系数按每分钟约 270 字的解说语速取值，作为初值供用户配音后微调。控制栏同时显示"推算值 / 手写值"，方便区分。

### 5.5 动作类型（actions）

所有动作都有可选字段 `at`（相对本句开始的毫秒，默认 `0`）。动作分两类：**瞬时动作**在 `at` 时刻生效；**过程动作**在 `[at, at + durationMs]` 区间内按缓动插值，任意 t 都能算出中间状态。

| type         | 类别 | 参数                                                                                                                                                                              | 效果                                                                                                |
| ------------ | ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `scroll`     | 过程 | `to`（定位器 / `top` / `bottom` / 像素数），`offset?`（默认 `-120`，与现有 `scrollToAnchor` 一致），`durationMs?`（默认 `1000`），`easing?`（`linear` / `easeInOut` / `easeOut`） | 页面平滑滚动到目标                                                                                  |
| `typewriter` | 过程 | `until`（标题定位器 / `end`），`durationMs`                                                                                                                                       | 打字机打到指定标题为止，同步解锁 TOC 条目。剧本里没有任何 `typewriter` 动作时，文章一开始就全量显示 |
| `toc`        | 瞬时 | `expand?: boolean`，`highlight?`（标题定位器）                                                                                                                                    | 展开/收起目录栏，高亮节点                                                                           |
| `highlight`  | 持续 | `target`（定位器），`style?`（`glow` / `box`），`untilLineEnd?`（默认 `true`）                                                                                                    | 给元素加高亮框，本句结束自动移除                                                                    |
| `copy`       | 瞬时 | `target`（代码块定位器）                                                                                                                                                          | 播放代码块"复制成功"按钮反馈（不真的写剪贴板）                                                      |
| `theme`      | 过程 | `to: light / dark`，`durationMs?`                                                                                                                                                 | 亮暗主题切换（不会弹出博客自带的主题切换 toast，见 §7.0）                                           |
| `toast`      | 持续 | `text`，`toastType?`（默认 `success`），`durationMs?`（默认 `4000`），`position?`（默认 `top-right`）                                                                             | 在指定时刻投放一个定时 toast，到时自动消失                                                          |
| `wait`       | 过程 | `durationMs`                                                                                                                                                                      | 本句结束后额外停留，用于纯画面镜头（气泡隐藏）                                                      |
| `overlay`    | —    | 预留                                                                                                                                                                              | Phase 3 实操演示舞台，Phase 1 校验时报"暂不支持"                                                    |

**校验规则**

- 同一时间段内两个 `scroll` 区间重叠 → 报错。
- `to` / `target` / `tocAnchor` 指向的元素在文章中找不到 → 预览时控制栏标红该句，渲染时拒绝开工。
- 动作的 `at` 超出本句 `duration` → 警告（允许，用于跨句动作）。
- `toast` 的 `position` 为 `bottom-right` → 警告（会挤动 TocPet 字幕框，见 §7.0）。

### 5.5.1 定位器（Locator）

剧本里所有"指向文章某处"的字段（`scroll.to`、`highlight.target`、`copy.target`、`toc.highlight`、`typewriter.until`、`tocAnchor`）共用同一种写法：

| 写法             | 示例                                                | 说明                                              |
| ---------------- | --------------------------------------------------- | ------------------------------------------------- |
| 标题原文（推荐） | `{ "heading": "第一步：安装依赖" }`                 | 直接从 Markdown 复制标题文字，不用手算 id         |
| 同名标题         | `{ "heading": "注意事项", "nth": 2 }`               | 第 2 个同名标题，`nth` 从 1 开始，默认 1          |
| 标题下的代码块   | `{ "heading": "第一步：安装依赖", "codeBlock": 1 }` | 该标题到下一个同级或更高级标题之间的第 1 个代码块 |
| 字符串简写       | `"#第一步安装依赖"`                                 | 直接写 DOM id，兼容旧写法                         |

产品要求：

- 定位器由标题文字解析，不能依赖 `pre:nth-of-type()` 这类全文序号。文章其他地方增删代码块时，剧本不受影响。
- 标题文字到 DOM id 的生成规则（现为 `useArticleInfo.ts` 的 `slugify`）可以按需修改，具体方案交给架构设计。按 §2.1 推论，这里不需要考虑公网锚点兼容。
- 找不到目标时按上方校验规则处理。

### 5.6 桌宠情绪扩展

现有 `PetMood`：`typing` `reading` `sleepy` `dizzy` `shocked`。演播室新增教学情绪：

| mood       | 用途             | 图标（Font Awesome）      | 视觉反馈                                            |
| ---------- | ---------------- | ------------------------- | --------------------------------------------------- |
| `warning`  | 敲黑板、易错点   | `fa-exclamation-triangle` | 琥珀色左边框 + 图标单次"敲击"下压动画；气泡文字加粗 |
| `cheer`    | 打招呼、成功撒花 | `fa-star`                 | 顶部撒 6~8 颗星星粒子，1.2 秒后消散                 |
| `thinking` | 解释原理、留悬念 | `fa-lightbulb`            | 气泡前显示"…"三点依次亮起，然后出文字               |
| `proud`    | 效果展示、得意   | `fa-crown`                | 图标轻微上下浮动，气泡高光扫过一次                  |
| `success`  | 某一步完成       | `fa-check-circle`         | 绿色边框闪一下，进度条对应节点打勾                  |

规则：

- 演播室模式下 `shocked` 的"不可覆盖"互斥逻辑、逃跑、核爆、晕车、闲聊全部关闭，情绪只由剧本设定。
- 所有动画都由帧时钟驱动（动画进度 = `(t - 情绪生效时刻) / 动画时长`），不得依赖 CSS 自走时间，否则逐帧截图会抖。

## 6. 数据契约二：顶栏音乐预烘焙格式（Music Bake JSON）

### 6.1 流程

1. 用户打开导演控制栏的「🎵 烘焙」面板（§7.4），输入一个或多个网易云歌曲 ID / 歌名；或点「识别当前播放」，通过 SMTC 读取网易云正在放的歌。
2. studio 后端执行烘焙：搜歌 → 抓歌词 → 合并双语 → 计算每行时长 → 写文件。
3. 输出 `studio/music/<id>.json`。整个 `studio/music/` 进 `.gitignore`，只保留 `example-song.json`。不再抓取封面。
4. 渲染时前端按帧时钟换算出「当前是第几首、放到歌曲第几毫秒」，再查询当前行。查询逻辑与 `LyricParser.match_sentence` 保持一致（二分查找 + 前奏处理），前端用 TS 重写一份。

### 6.1.1 歌词能力并入 studio 后端

从 ncm-lyrics-streamer 只取「烘焙」需要的部分，放进 studio 后端，不再依赖外部进程：

| 原文件                                  | 作用                                     | studio 处理                                                                                |
| --------------------------------------- | ---------------------------------------- | ------------------------------------------------------------------------------------------ |
| `core/lyric_parser.py`                  | 解析 LRC、合并双语、算时长（只用标准库） | 并入                                                                                       |
| `core/lyric_fetcher.py`                 | 网易云搜歌、抓歌词（aiohttp）            | 并入                                                                                       |
| `core/media_listener.py`                | SMTC 识别当前播放（winsdk，仅 Windows）  | 并入为可选能力；非 Windows 或未安装时，面板隐藏「识别当前播放」按钮，ID / 歌名烘焙照常可用 |
| `core/lyric_engine.py` + WebSocket 推送 | 实时歌词广播                             | 不要，预烘焙用不到                                                                         |

产品要求：

- 烘焙代码和依赖只在 studio 仓库（新增目录 + 单独的 `requirements-studio.txt`），upstream 的 `requirements.txt` 不受影响（§2.1 R2、R5）。
- 烘焙接口只监听本机，不需要登录，但不能在公网暴露（studio 本来就只在本地运行）。
- 网络请求只发生在烘焙时。渲染期间前端禁止任何网络请求。
- Flask（同步）与原 aiohttp（异步）怎么衔接，交给架构设计。

### 6.2 格式

字段命名沿用 `LyricLine.to_dict()` 的 snake_case，烘焙脚本可以直接序列化，不用转换。

```json
{
  "version": 1,
  "id": "example-song",
  "baked_at": "2026-11-06T20:15:00+08:00",
  "source": { "provider": "netease", "song_id": 123456 },
  "meta": {
    "title": "示例歌曲",
    "artist": "示例歌手",
    "album": "示例专辑",
    "duration_ms": 215000
  },
  "lyrics": {
    "has_translation": true,
    "has_romaji": false,
    "lines": [
      {
        "time_ms": 12300,
        "duration_ms": 4100,
        "text": "原文歌词第一句",
        "translation": "译文第一句",
        "romaji": ""
      },
      {
        "time_ms": 16400,
        "duration_ms": 3800,
        "text": "原文歌词第二句",
        "translation": "译文第二句",
        "romaji": ""
      }
    ]
  }
}
```

### 6.2.1 格式规则

- 译文、罗马音照常烘焙保存（以后加译文开关时不用重烤），Phase 1 顶栏只显示 `text`。
- 无歌词（纯音乐）时 `lines` 为空，歌词条显示「♪ 纯音乐 ♪」。
- 渲染期间前端**禁止任何网络请求**，所有资源都来自本地烘焙文件。

### 6.3 歌单播放时间线

第 k 首歌在视频里的开始时刻 = 前面每首歌的「实际播放时长」之和，实际播放时长 = `duration_ms - startAtMs`。时间线完全由剧本和烘焙文件推算，满足可跳转原则。

```
视频 t:  0 ─────────── 歌 A ───────────┬─────────── 歌 B ───────────┬── 静默 ≤15s ──┬── outro ──▶ 片尾
                                     渐变(crossfadeMs)              歌单放完        15s 到
                                     不显示 outro                    "♪" 慢闪        淡出歌词，显示结束语
```

| 情况                              | 歌词条行为                                                                   |
| --------------------------------- | ---------------------------------------------------------------------------- |
| 一首结束，后面还有歌              | 当前行淡出，`crossfadeMs` 内渐变到下一首的第一行（或前奏）。**不显示 outro** |
| 每首歌开始                        | `announce: true` 时，自动投放 4 秒 success toast「♪ 歌名 - 歌手」（右上角）  |
| 最后一首结束，15 秒内视频也结束   | 显示「♪」慢闪直到片尾，不显示 outro                                          |
| 最后一首结束，15 秒后视频仍未结束 | 第 15 秒起歌词条淡出，换成 outro 结束语，保持到片尾                          |
| 歌单总时长 ≥ 视频时长             | 歌放到片尾为止，不涉及 outro                                                 |

- outro 文字优先用剧本 `music.outro.text`，没写就用代码内置默认值（例如「感谢观看～我们下次见 awa」）。
- 「静默 15 秒」的 15 秒 Phase 1 写死在代码里，不开放剧本配置。
- `manifest.json` 必须列出本段涉及的每首歌：`ref`、视频内起始毫秒、歌曲内起始毫秒（US7）。

## 7. UI / UX 构想

> **尺寸单位约定**：本章所有尺寸（宽度、字号、边距）都指**输出视频里的像素**，也就是观众实际看到的大小。实现时按 `video.zoom` 换算成 CSS 像素（例如 zoom 1.1 时，640px 宽 ≈ 582 CSS px）。

### 7.0 演播室画面清场规则

| 元素                                                                                                                                                  | 演播室模式                                                                                     | 退出后       |
| ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- | ------------ |
| 侧栏（含「»」展开按钮）                                                                                                                               | 隐藏                                                                                           | 恢复         |
| 文章末尾「上一篇 / 返回目录 / 回到顶部 / 下一篇」按钮组                                                                                               | 隐藏                                                                                           | 恢复         |
| 文章页头的「←」返回按钮                                                                                                                               | 隐藏，页头标题保留                                                                             | 恢复         |
| 文章信息行（日期 / 字数 / 排版行数 / 阅读时长）                                                                                                       | 隐藏                                                                                           | 恢复         |
| 页面底部中央的「▼」滚动提示                                                                                                                           | 隐藏                                                                                           | 恢复         |
| 顶栏 logo、标题文字、时钟、右侧页面名                                                                                                                 | 隐藏，顶栏只留歌词条（§7.2）                                                                   | 恢复         |
| TocPet「关闭」按钮                                                                                                                                    | 隐藏（点击会触发受惊，再点会核爆清空页面）                                                     | 恢复         |
| TocPet 闲聊轮播（`usePetIdle`）、时段问候与节日播报（`usePetGreeting`：公历 / 农历 / 节气）、hover 回应、躲避导航按钮（`usePetNavDodge`）、躲避 toast | 全部关闭。**画面里出现的所有文字都由剧本决定**，代码不得根据当前日期、时间或随机数自行生成台词 | 恢复         |
| 粒子层                                                                                                                                                | 保留，帧时钟驱动 + 固定随机种子（已确认 §9.2 P4）                                              | 恢复         |
| 剧本投放的 toast                                                                                                                                      | 显示                                                                                           | —            |
| 博客代码自己发出的 toast（任何类型）                                                                                                                  | 不进画面，转到导演控制栏的消息列表                                                             | 恢复正常弹出 |

- toast 按**来源**区分，不按类型区分。已知会自动弹出的来源：`useTheme.ts` 主题切换（success）、`router/index.ts` 路由跳转（info / success）、`ArticleTocPet.vue` 找不到标题（warning）。以后博客新增的弹窗也自动适用这条规则。
- 剧本 toast 默认在 `top-right`。TocPet 现在会给右下角 toast 让位（`finalDodgeOffset`），演播室模式下这个让位逻辑关闭，字幕框位置固定。
- 剧本 toast 的出现、停留、消失都由帧时钟控制，不能用 toast 自带的 `setTimeout` 计时。
- 侧栏隐藏后，文章栏居中，宽度保持适合阅读的范围，并留出右下角 TocPet 的位置，不让字幕压住正文。具体宽度在真机预览时再调。
- **不读取用户本地设置**：upstream 已让 `useSettingsStore` 在启动时从 localStorage 恢复设置（打字机速度、粒子、toast 位置等）。主题由 `useTheme.ts` 单独存在 localStorage 的 `theme` 键里，也属于个人设置。演播室模式必须忽略这些个人设置，只用剧本（如 `video.theme`）和 studio 默认值，否则同一份剧本在不同浏览器状态下会渲染出不同画面（违反原则 1），也不能把演播室的设置写回 localStorage。
- **字幕遮挡区**：TocPet 字幕框会盖住正文右下角一块区域（§9.2 P3）。剧本 `highlight` / `copy` 的目标元素滚动到位后落在字幕框下方时，校验给出警告。

### 7.1 TocPet 字幕形态（演播室模式）

现状：宽 400px、右下角、Toast 风格单行台词。1080p 视频压缩到手机上看时字太小。

```
                                       ┌──────────────────────────────────────┐
                                       │ ▌⚠  注意！必须先激活虚拟环境再       │ ← 气泡区：最多 2 行
                                       │ ▌   **pip install**！                 │   字号 26px，行高 1.5
                                       ├──────────────────────────────────────┤
                                       │ ① 开场  ② 安装依赖  ③ 配置  ④ 效果   │ ← 步骤条（TOC 收起时）
                                       │ ━━━━━━━━━━━━━●─────────────────────── │ ← 进度条（步骤节点）
                                       └──────────────────────────────────────┘
                                         宽 640px，距右 40px / 距底 48px
```

- **尺寸**：宽度 400 → 640px；台词字号 ≥ 26px（1080p 下手机端仍可读）；单句超过 2 行时校验警告，提示拆句。
- **左侧情绪色条**：4px 竖条按 mood 着色（warning 琥珀、success 绿、thinking 蓝、cheer 粉、默认主题色），观众扫一眼就知道这句的语气。
- **台词切换**：旧句向上淡出 150ms，新句自下淡入 200ms。`gapMs` 期间气泡保持高度、内容为空，避免盒子跳动。
- **步骤条**：TOC 收起时显示 segment 级步骤（不是文章全部标题），已完成步骤打勾、当前步骤加粗。
- **目录展开动效**：高度从步骤条向上展开 400ms（沿用现有 `cubic-bezier(0.25, 0.8, 0.25, 1)`），当前高亮标题有左侧光条滑入；展开期间气泡固定在顶部不动。
- **安全区**：PRD 默认字幕占画面右下约 1/3 宽度，用户在 PR 里若要叠加画中画，建议放左下。

### 7.2 顶栏歌词条

替换 `MainLayout.vue` 中 `.center-group` 的 `.time-display`。只在演播室模式启用，普通模式仍显示时间。

设计原则：视频的主角是下方文章，顶栏只做氛围，不抢视线。

```
┌──────────────────────────────── title-bar (glass) ─────────────────────────────────┐
│                          原文歌词当前这一句                                         │
└────────────────────────────────────────────────────────────────────────────────────┘
          只有一行原文歌词，居中；无 logo、无封面、无按钮、无译文、无进度条、无时间
```

| 去掉的元素                 | 原因                                         |
| -------------------------- | -------------------------------------------- |
| logo、标题文字、右侧按钮组 | 画面里不需要操作入口                         |
| 封面                       | 太抢眼；歌名署名改由 toast 负责（§6.3）      |
| 译文                       | 一行足够；译文仍烘焙保存，Phase 2 再考虑开关 |
| 进度条                     | 和 TocPet 的进度条重复                       |
| 歌曲时间                   | 观众可能误以为是视频时间                     |

- **换行动效**：只有淡入淡出。旧行淡出、新行淡入，各 300ms，不做卡拉 OK 渐亮、不做位移。
- **超长歌词**：单行显示，超出宽度时末尾省略，不横向滚动。
- **前奏 / 间奏 / 歌间空白**：显示「♪」，透明度缓慢呼吸（帧时钟驱动）。
- **outro**：按 §6.3 的时间线淡入结束语，样式与歌词一致。
- **亮色主题**：主文字深色，透明度 85%。
- **暗色主题**：主文字白色，透明度 85%，加极弱的文字阴影，保证在云海壁纸上能看清。
- 标题栏的毛玻璃底是保留整条，还是缩成居中的小胶囊，见 §9.2。

### 7.3 导演预览控制栏

只在 `?studio=<id>&director=1` 时出现；渲染时不带 `director` 参数，控制栏不进画面。

```
┌───────────────────────────────────────────────────────────────────────────────────┐

│ ┃▪▪ ▪       ┃▪ ▪▪ ▪▪                    ┃▪▪▪             ┃▪ ▪                     │ ← 台词刻度
│ ━━━━━━━━━━━━━━━━━━━━━━━━━━●───────────────────────────────────────────────────── │ ← 播放头
│ 当前：install / 第 2 句  mood=warning  duration=3200(手写)   备注：这句语气要重   │

                                固定在画面底部，半透明，可按 H 折叠

```

```
│ 歌曲 ID / 歌名（每行一首）                                │
│ ┌──────────────────────────────────────────────────────┐ │
```

## 10. 交给架构设计的关注点

以下是产品层面识别到的技术风险，具体方案由 🏛️ 架构设计决定：

1. **帧时钟接管范围**：`requestAnimationFrame`、`setTimeout`、CSS transition/animation、`Date.now()`、`window.scrollTo({behavior:'smooth'})`、`IntersectionObserver` 都会让截帧不确定。现有 `ArticleTocPet.vue` 用 IntersectionObserver 算 `activeHeadingId`，`scrollToAnchor` 用 smooth 滚动，`ContentTypeWriter.vue` 依赖 rAF，都需要在演播室模式下改走帧时钟。
2. **可跳转实现**：任意 t 的状态需要从剧本"推导"，而不是"播放累积"。打字机、情绪动画、歌单时间线、toast 生命周期最容易违反这一点。
3. **截帧性能**：暂不设指标（§3.2.1）。如果架构上发现性能问题来自博客本体，按 §2.1 R3 记录下来，回 upstream 处理。
4. **歌词查询**：前端 TS 版 `match_sentence` 需与 Python 版行为一致，建议用同一份测试数据对拍。
5. **仓库单向关系**：严格遵守 §2.1。studio 改动集中在新增文件和模式开关后面，降低合并 upstream 时的冲突；studio 依赖放 `requirements-studio.txt`。
6. **toast 按来源拦截**：区分"剧本投放"和"博客自发"两种来源，自发的转进导演控制栏；剧本 toast 的计时改走帧时钟。
7. **锚点定位器**：实现 §5.5.1 的标题原文定位与"标题下第 N 个代码块"，`useArticleInfo.ts` 的 `slugify` 可以按需修改。
8. **烘焙后端**：Flask（同步）与原 `lyric_fetcher.py`（aiohttp 异步）的衔接方式；SMTC（winsdk）作为可选依赖，缺失时功能降级而不报错。
9. **页面缩放**：`video.zoom` 要等效浏览器缩放。Playwright 可用「CSS 视口 = 输出尺寸 ÷ zoom + `deviceScaleFactor = zoom`」模拟，但 1920÷1.1 不是整数（≈1745.45），截图可能差 1px。需要确认取整方式，或评估 CSS `zoom` 等替代方案。导演预览也要用同样的缩放，保证预览和成片一致。
10. **隔离用户设置**：演播室模式下 `useSettingsStore` 不读也不写 localStorage（§7.0）。upstream 刚把这个 store 改成 Setup 写法，并加了 `storage` 事件同步，隔离逻辑要放在 studio 自己的开关里，不改 upstream 的 store 内部（§2.1 R5）。
11. **粒子层确定性**：`ParticleLayer.vue` 的运动和随机数要能按 t 推导（P4）。
